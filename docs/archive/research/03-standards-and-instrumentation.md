# Track 3: Standards and Coding-Agent Instrumentation Feasibility (as of 2026-10-03)

Legend: **[search-only]** rests on search abstracts because the primary page was blocked; everything else was fetched from official docs or source on GitHub.

## A. Standards

### A1. OpenTelemetry GenAI semantic conventions
- **Stability:** every `gen_ai.*` span, attribute, metric and event is marked **Development**. Nothing is Stable. Conventions now live in the dedicated repo `open-telemetry/semantic-conventions-genai` (docs/gen-ai: README, anthropic, aws-bedrock, azure-ai-inference, gen-ai-agent-spans, gen-ai-events, gen-ai-exceptions, gen-ai-metrics, gen-ai-spans, gen-ai-token-metrics, mcp, openai; registries for gen_ai.*, mcp.*, openai.*).
- **Agent spans:** `create_agent` (CLIENT kind, primarily remote agent services; `gen_ai.agent.name`, `gen_ai.agent.id` as a vendor-assigned stable resource id, not an in-memory instance). `invoke_agent` for client-side and internal invocation.
- **Tool execution span:** name `{gen_ai.operation.name} {gen_ai.tool.name}`, INTERNAL; required `gen_ai.operation.name=execute_tool`; conditionally required `gen_ai.tool.name`, `gen_ai.tool.call.id`; recommended `gen_ai.tool.type/description/call.arguments/call.result`.
- **Operation names:** chat, embeddings, generate_content, text_completion, retrieval, execute_tool, create_agent, invoke_agent, plan, search_memory, create_memory, update_memory, delete_memory, upsert_memory. Memory ops exist as names; no memory content or provenance convention.
- **Messages:** `gen_ai.input.messages`, `gen_ai.output.messages`, `gen_ai.system_instructions`, `gen_ai.tool.definitions` are Opt-In; JSON schema `{role, parts:[{type: text|tool_call|tool_call_response, ...}]}`. Events `gen_ai.client.inference.operation.details` and `gen_ai.evaluation.result`.
- **Agentic SIG work (issue tracker):** #35 meta-issue (Aug 2025) proposing Tasks, Actions, Agents, Teams, Artifacts, Memory, with **no mention of compaction, permissions, HITL, checkpoints or stop reasons**; #37 `gen_ai.task.*` lifecycle (Todo); **#159 (May 2026)** span events `gen_ai.agent.paused/resumed/checkpointed/started/completed/failed` with pause reasons and checkpoint ids, no maintainer response; **#181 (May 2026)** privacy-first context-input evidence (what context was loaded, by which mechanism, hashed not content), explicitly motivated by coding agents, open questions unresolved; #187 `invoke_node`; #86 skill span; #51 session.id; #254 A2A telemetry; #249 principles for agent/inference/control-plane telemetry.
- **Conclusion:** no convention exists, even in draft, for permission decisions, context compaction, verification steps, or stop reasons beyond `gen_ai.response.finish_reasons`.

### A2. OpenInference (Arize)
`openinference.span.kind` required; **11 kinds: LLM, EMBEDDING, CHAIN, RETRIEVER, RERANKER, TOOL, AGENT, GUARDRAIL, EVALUATOR, PROMPT, DECISION**. Cross-span `session.id`, `user.id`, `graph.node.id/parent_id`. No spec version string, no statement on `gen_ai.*` compatibility; positioned as "complementary". 40+ Python instrumentors (incl. Claude Agent SDK, OpenAI Agents, ADK, PydanticAI, CrewAI, AG2), JS (incl. Claude Agent SDK, MCP, Vercel AI SDK), Java, Go.

### A3. Other standards
- **AGNTCY (Linux Foundation, ex Cisco Outshift):** Observe SDK extends OTel GenAI conventions for multi-agent systems; decorators, MAS metrics; ClickHouse/Grafana reference stack; 80+ members. No replay or recording.
- **Agentgateway (LF):** gateway, not a schema. **A2A telemetry:** OTel issue #254 only. **"AgentSpec":** no standard by that name found.
- **o11y-dev/opentelemetry-hooks** (v0.14.0, ~40 stars): converts Claude Code, Cursor, Copilot, Gemini CLI, Codex, OpenCode, Windsurf hook payloads into OTel spans; content hashed by default. Closest existing prior art to the wedge.

### A4. MCP observability
- **2026-07-28 revision:** SEP-414 adds W3C trace-context propagation via `_meta` keys `traceparent`, `tracestate`, `baggage`; SEP-2575 `server/discover`; per-request log level; protocol-level Logging, Roots, Sampling deprecated (SEP-2577); HTTP+SSE deprecated; `Mcp-Session-Id` removed; server-initiated requests replaced by Multi-Round-Trip Requests; `subscriptions/listen`.
- **Tasks** moved to extension `io.modelcontextprotocol/tasks` with lifecycle pending → running → completed/failed/cancelled [search-only].
- **Span transport inside MCP rejected:** discussion #269 (`notifications/otel/trace`) closed Sept 2026 without adoption; consensus favored context propagation.
- **OTel MCP conventions (Development):** spans `{mcp.method.name} {target}`; `mcp.session.id`, `mcp.protocol.version`; tools/call maps to `execute_tool`.
- Net: MCP gives correlation and task state, not audit or recording.

## B. Coding-agent instrumentation

### B5. Claude Code (deepest surface of any coding agent)
Sources: code.claude.com docs for monitoring-usage, hooks, agent-sdk/observability, agent-sdk/typescript, sessions, checkpointing.
- **OTel export:** `CLAUDE_CODE_ENABLE_TELEMETRY=1` plus `OTEL_METRICS_EXPORTER` / `OTEL_LOGS_EXPORTER` / `OTEL_TRACES_EXPORTER`. Traces are beta (`CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1`).
  - Metrics (8): session.count, lines_of_code.count, pull_request.count, commit.count, cost.usage, token.usage, code_edit_tool.decision, active_time.total; cost/token carry `query_source` (main/subagent/auxiliary), `agent.name`, `skill.name`, `mcp_server.name`, `mcp_tool.name`.
  - Log events (20+): `user_prompt`, `assistant_response`, `tool_result` (tool_name, tool_use_id, success, duration_ms, decision_source config/hook/user_permanent/user_temporary), `api_request`, `api_error`, `api_refusal`, `api_request_body` / `api_response_body` (`OTEL_LOG_RAW_API_BODIES=1` or `file:<dir>`, full Messages API bodies, thinking redacted), **`tool_decision`** (accept/reject with source), **`permission_mode_changed`**, `mcp_server_connection`, `hook_registered`, `hook_execution_start/complete`, `skill_activated`, `plugin_loaded`, `api_retries_exhausted`, `managed_settings_resolved`. Events carry `prompt.id`, `event.sequence`, `message.uuid`, `session.id`.
  - Spans (beta): `claude_code.interaction` → `claude_code.llm_request` (model, `gen_ai.response.id`, `stop_reason`, `gen_ai.response.finish_reasons`, ttft, tokens, `agent_id`, `parent_agent_id`, `workflow.run_id`; `gen_ai.request.attempt` event per retry), `claude_code.tool` (tool_name, `gen_ai.tool.call.id`, `subagent_type`, `file_path`, `full_command`; `tool.output` event with `OTEL_LOG_TOOL_CONTENT=1`) with children `claude_code.tool.blocked_on_user` (permission wait) and `claude_code.tool.execution`; `claude_code.hook`. **Subagent spans nest under the parent's `claude_code.tool` span**, giving the delegation tree in one trace.
  - W3C propagation: Bash children inherit TRACEPARENT; `traceparent` header to Anthropic API and outbound HTTP MCP; SDK and `-p` sessions honor inbound TRACEPARENT.
  - Redaction defaults: prompts, responses, tool params, tool output, file content, full error text redacted unless opted in. Extended thinking never exported. **Compaction has no dedicated OTel event** (only `user_prompt` with `command_name=compact` for manual compaction). OTEL_* vars not propagated to subprocesses, MCP servers or hooks.
- **Hooks (33 events):** SessionStart (matchers startup/resume/clear/compact/fork), Setup, **InstructionsLoaded** (CLAUDE.md/rules load reason, i.e. context provenance), UserPromptSubmit, UserPromptExpansion, **PreToolUse** (can allow/deny/ask/defer, rewrite input), **PermissionRequest**, **PermissionDenied** (auto-mode classifier_verdict, denial_reason), **PostToolUse** (can replace output), **PostToolUseFailure**, PostToolBatch, Notification, MessageDisplay, **SubagentStart** (agent_type, agent_id, agent_input), **SubagentStop** (agent_result), **Stop**, **StopFailure** (rate_limit/overloaded), TeammateIdle, TaskCreated/TaskCompleted, ConfigChange, CwdChanged, DirectoryAdded, FileChanged, WorktreeCreate/Remove, **PreCompact** (compaction_reason manual/auto; can block), **PostCompact** (tokens_reduced), PreModelSwitch/PostModelSwitch, **Elicitation / ElicitationResult**, SessionEnd (end_reason, total_turns, duration). Common input: session_id, prompt_id, transcript_path, cwd, permission_mode, effort, agent_id, agent_type. Hook types: command, http, mcp_tool, prompt, agent.
- **Transcripts:** JSONL at `~/.claude/projects/<project>/<session-id>.jsonl`; subagent files alongside. Docs **warn the entry format is internal and changes between versions**; recommended interfaces are `/export`, `claude -p --output-format json|stream-json`, hooks' `transcript_path`, or the Agent SDK. Default retention 30 days.
- **Agent SDK:** typed message stream incl. `SDKCompactBoundaryMessage {trigger, pre_tokens}`, hook events, tool progress, `SDKPermissionDeniedMessage`, `SDKAPIRetryMessage`, `SDKMemoryRecallMessage`, `SDKSessionStateChangedMessage`; `canUseTool` permission callback with `decisionReason`. SDK hook list narrower (SessionStart, Setup, PreToolUse, PostToolUse, Notification, SessionEnd, PreCompact, PostCompact).
- **Checkpointing:** file snapshots before each turn (100 most recent), `/rewind`; **Bash-made changes and most subagent edits are not tracked**; swept after ~30 days.
- **Answer:** a third party can capture tool calls, subagent spawns, compaction boundaries and permission decisions via two independent channels (hooks and OTel), content opt-in. Gaps: compaction summary content and post-compaction context only in the unstable JSONL; no first-class verification signal; classifier reasoning only as `classifier_verdict`.

### B6. OpenAI Codex CLI and Agents SDK
- **Codex OTel** (PR #2103, Sept 2025): `[otel]` in `~/.codex/config.toml`; `exporter = none|otlp-http|otlp-grpc`; `log_user_prompt=false` default; events `codex.api_request`, `codex.sse_event` (tokens incl. reasoning/cached), `codex.user_prompt`, `codex.tool_decision` (approved/denied/abort with source), `codex.tool_result`.
- **Coverage gap** (issue #12913, Feb 2026): interactive exports traces, logs, metrics; `codex exec` exports no metrics; `codex mcp-server` initializes no OTel.
- **Codex hooks** (codex-rs/hooks/src/lib.rs): 12 events — PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, SessionStart, SessionEnd, UserPromptSubmit, SubagentStart, SubagentStop, Stop, Interrupt; **same JSON output contract as Claude Code** (`hookSpecificOutput.permissionDecision`, `updatedInput`).
- Threads persist in `~/.codex/sessions`; TS SDK `runStreamed()` yields item and turn events. Codex cloud: no third-party telemetry surface found.
- **OpenAI Agents SDK:** own tracing model (agent_span, generation_span, function_span, guardrail_span, handoff_span, mcp_tools_span); `TracingProcessor` plugin; `trace_include_sensitive_data` default True; 30+ third-party processors. **No native OTel export.**

### B7. Other coding agents
- **Cursor:** `hooks.json` only. Events: beforeShellExecution/afterShellExecution, beforeMCPExecution/afterMCPExecution, beforeReadFile, afterFileEdit, beforeSubmitPrompt, stop (status, loop_count), afterAgentResponse, afterAgentThought; newer docs add sessionStart/End, preToolUse/postToolUse, subagentStart/Stop, preCompact [search-only]. Only before-shell/MCP/read-file return permission decisions. No OTel, no transcript API.
- **Devin:** REST API to list/get/search session events and generate Session Insights [search-only]. No OTel or hooks.
- **Cline:** opt-in OTel metrics and logs, no traces; ~40 events (task.*, task.tool_used, task.mcp_tool_called, task.checkpoint_used, task.subagent_started, hooks.execution); paths, args and code hashed. Cline SDK plugin hooks onRunEnd/onToolCall/onError.
- **OpenHands SDK:** native OTel traces (conversation → per-iteration step → tool with input/output; LLM via LiteLLM) to any OTLP; event store with ReplayManager for resume/replay [architecture detail search-only].
- **Aider:** PostHog analytics only; `--analytics-log file.jsonl`. No hooks, no OTel.
- **Gemini CLI:** native OTel (`telemetry.enabled`, gcp/otlp/local file; `logPrompts` default true). Events: config, user_prompt, tool_call, api_request/response/error, file_operation, hook_call, model_routing, agent start/finish/recovery, chat_compression. Hooks (11): BeforeTool/AfterTool, BeforeAgent/AfterAgent, **BeforeModel/AfterModel (can override LLM request or response)**, BeforeToolSelection, SessionStart/End, Notification, **PreCompress (advisory)**; no subagent hooks.

### B8. Frameworks
- **LangGraph:** no native OTel in the runtime; LangSmith ingests OTel. Time travel: `get_state_history()`, invoke with prior `checkpoint_id` to replay, `update_state()` to fork. Docs: "Replay re-executes nodes—it doesn't just read from cache. LLM calls, API requests, and interrupts fire again and may return different results." **Not deterministic.**
- **CrewAI:** no native OTel; OpenInference instrumentor. **PydanticAI:** native OTel following GenAI semconv v1.37.0, `include_content=False`. **AutoGen core:** native OTel with create_agent/invoke_agent/execute_tool, code comment "still in incubation". **Google ADK:** native OTel `invoke_agent`, `invoke_workflow`, `execute_tool`, `generate_content`. **Mastra:** own tracing (AGENT_RUN, LLM_GENERATION, TOOL_CALL, WORKFLOW_RUN, MCP_TOOL_CALL, memory ops) with OtelExporter. **Vercel AI SDK:** `experimental_telemetry`, legacy `ai.*` spans plus semconv names.
- Across all frameworks: **none emits first-class events for compaction, permission decisions, or checkpoint/interrupt transitions as telemetry.**

## C. Replay feasibility

### C9. Prior art
- **Cassettes:** VCR.py, pytest-recording; pytest-llm-vcr (SSE replay, sequential tool-call cassettes, `llm-vcr diff`); agent-vcr (tool calls, DB queries, completions to YAML); langchain-replay; deepeval `record_cassette`. Test-time mocking at the HTTP boundary, not production recording [search-only].
- **Durable execution:** Temporal (event-history replay; LLM and tool calls in activities whose results are journaled; `temporalio-openai-agents` package), Inngest step journaling, Restate journal per `ctx.run()`, DBOS. Crash-recovery replay and a complete journal of side effects, but only if the agent is authored inside the engine.
- **Environment snapshots:** E2B pause/resume (filesystem, memory, processes; ~4 s/GiB pause, ~1 s resume, named snapshots to fork); Modal snapshots restore into a new sandbox; Daytona snapshot/fork/pause (experimental) [search-only]. Claude Code checkpoints snapshot only edit-tool changes.
- **Academic 2026 [abstracts only]:** Causal Agent Replay (arXiv 2606.08275, SCM over a run, fork at step k); Knowledge-Based Zero-Replay Debugging (2606.14805, replay cost linear in candidates); DoVer (2512.06749, in-place replay preserving prefix); The Replay Gap (2608.08239, static replay "evaluates the wrong world"); Repair or Resample? (2608.25920); Property-Level Reconstructability of Agent Decisions across vendor SDK adapters (2605.12078).

### C10. Trajectory comparison and failure taxonomies
- **MAST** (arXiv 2503.13657, NeurIPS 2025): 14 failure modes, 3 categories (specification ~42%, inter-agent misalignment ~37%, verification ~21%), 1,642 annotated traces, kappa 0.88.
- **TRAIL** (Patronus, 2505.08638): 148 traces, 841 errors from GAIA and SWE-bench runs; best model ~11% joint accuracy.
- **AgentErrorTaxonomy / AgentErrorBench / AgentDebug** (2509.25370): 17 error types; finds earliest critical error; failures cluster at steps 6 to 15; up to +26% task success on re-rollout.
- **Who&When** (decisive step = earliest index where correction flips the outcome); **AgenTracer** (fault injection and counterfactual corrections); **AgentRx** (first unrecoverable failure, constraint synthesis); **TrajDebug**; **Oat — Tracing Agentic Failure from the Flow of Success** (learns dynamics of successful trajectories, scores per-step deviation in failures) — closest to first-divergence detection.
- **Model or Harness?** (2607.28802): 41 failure modes on component edges with a fault side; judges reach kappa 0.76. **Root-Cause Attribution Is a Search Problem** (2609.13463): Continual Search lifts Opus-4.8 F1 from 0.471 to 0.608 on MegaRCA-Mix. **LongRCA Bench** (2608.15242): 1,140 real failed trajectories, median 145 steps; best baseline 13.2% exact root-step accuracy, RCTA 24.1%; public leaderboard; LongRCA-Mini (200 trajectories).
- **Coding-agent specific:** Failure as a Process (2607.09510): 71% of successful CLI coding-agent trajectories hit at least one error; recovery separates success from failure. Also 2608.24271 (observability and fault injection for multi-agent SE), 2606.14589 (longitudinal taxonomy of silent failures in a production agent runtime).
- **Compaction:** Governance Decay (2606.22528): compaction raises violation 0% → 30% (up to 59%), 7 models, 1,323 episodes; Constraint Pinning restores 0% with ~47 tokens. Lost in Compaction (2608.11242): compactors retain 17% of session constraints; SC-aware extractor >90%; COMPINT suite.

## Synthesis

**What standards already solve:** vocabulary for the model/tool/agent skeleton; correlation plumbing (traceparent through MCP, Bash children, model API); a consistent opt-in content-privacy posture; a de facto hook payload contract shared by Claude Code, Codex, Cursor and Gemini CLI; reusable failure taxonomies and the "earliest decisive step" formalism.

**What is unaddressed:** harness control events (permissions, mode changes, compaction trigger and effect, context provenance, model/effort switches, verification, stop reasons); subagent and delegation topology beyond span nesting; any definition of a replayable record (OTLP is lossy by design: sampling, 60 KB truncation, bounded flush, spans dropped on fast exit); deterministic replay of coding agents (needs frozen model cassette plus per-step environment snapshot; nobody pairs them); trajectory diffing on production telemetry; stable transcript formats.

**Instrumentability ranking:** Claude Code (deepest) > Codex interactive > Gemini CLI > OpenHands SDK (embedded) > Cursor > Cline > Aider > Devin. Frameworks give routine spans but no control events.

**Wedge implication:** one hook adapter plus an OTLP receiver covers Claude Code, Codex and Gemini CLI today with tool calls, permission decisions, subagent spawns, compaction boundaries and stop reasons, with no agent modification. The product must itself supply (a) a stable cross-harness schema for control events (draft as a `gen_ai.*` extension along the lines of issues #159 and #181, and upstream it), (b) a loss-free side channel (raw bodies to disk, filesystem snapshots), and (c) fork-at-step replay combining recorded model responses with environment snapshots.
